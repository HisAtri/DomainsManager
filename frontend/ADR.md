# 前端架构决策

## 2026-10-03：界面文案只说明功能，不说明实现

- 面向用户的 label、说明、空状态与错误提示只描述用户能观察到的功能与影响；队列、缓存、租约、Worker、数据表、版本号、部署重启等实现机制写入开发文档，需要辅助操作时再给出上下文提示。
- 系统设置页的文案由后端注册表下发，因此 `global_setting_registry.py` 的 label/description 与前端文案遵循同一条标准。
- 管理端需要精确信息时采用「中文可读标签 + 原始值作为次级信息」：错误码、事件码、UUID 先给中文名，原始值以次级小字或技术详情提供，不直接以内部标识充当主文案。
- 检查记录与任务结果中的后端原始文本（错误码、注册局报文）先映射为中文原因，原始内容收进可展开的技术详情。
- 该约定生效时同步删除 app.tsx 中三个未被任何路由引用的旧设置组件（`LegacyPersonalSettingsPage`、`LegacyAdminSettings`、`AdminSettings`）及仅服务它们的样式；不要恢复「后端待重启」「数据库配置 · 版本 N」「变更会写入审计日志」一类文案。

## 2026-10-03：设置页功能说明

- 页面和组件的 description 说明其面向用户的功能与用途；保存规则、显示条件等实现行为留在开发文档，需要辅助操作时再提供上下文提示。

## 2026-10-02：第三方登录控制与用户名引导

- 平台开关放在各凭据分组标题右侧，沿用统一保存与未保存提醒；关闭不会清空表单，未配置凭据不展示登录入口。
- 新 OAuth 用户使用独立、延续登录页样式的用户名引导页；由持久化用户状态决定显示，刷新或重新登录可继续，提交后进入仪表盘。

## 2026-10-02：固定第三方入口

- 登录与绑定仅展示 GitHub 和 LinuxDo；可用状态为这两项明确的布尔值，不从服务端接收任意 provider key 再拼接 API 路径。
- 管理员在“第三方登录”分别维护两套凭据，回调源地址沿用“站点信息”的站点地址。
- 关联账号只显示平台、当前身份和操作；最后一种登录方式的解绑按钮保留禁用外观和焦点能力，由按钮自身解释原因，不增加第二个控件。
- 关联列表沿用分组标题下的一条分割线，不再另画列表顶线；平台状态查询失败不推断其已停用，解绑成功后先更新列表再刷新。

## 2026-09-17：OAuth 登录与身份管理

- 前端只包含 GitHub 和 LinuxDo 两个固定入口；可用状态由服务器返回，登录使用浏览器导航，绑定使用认证 POST 返回的授权地址。
- OAuth 组件集中在 `src/oauth-components.tsx`，API 与响应类型沿用现有客户端。
- 回调仅包含结果标记；前端消费后清除标记，不从 URL 获取或保存令牌，沿用 `restoreTokens` 恢复会话。
- 个人设置支持无密码用户首次设置密码。按账号接口返回的密码状态与绑定数量禁用最后身份解绑；服务端继续负责最终校验，错误直接展示。
- 标识使用提供的本地 SVG，前端不包含提供商密钥配置。
- 绑定、解绑及首次设密的十分钟重新认证限制由服务端校验，前端展示退出后重登的提示。设置或修改密码后调用 `restoreTokens`，兼容 204 响应与会话凭据轮换。
