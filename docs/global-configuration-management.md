# 全局运行配置管理

## 1. 目的与边界

本方案定义管理员通过 Web API 管理、数据库持久化的**全局运行策略**。它解决业务规则在不重启时
可调整、可审计和可回滚的问题；不建立通用的“任意键值”后台，也不替代环境变量、部署平台或 Secret
管理器。

当前已落地运行策略及站点展示注册键：账户注册开关、域名监控、刷新任务、调度、通知设置（Webhook 与 SMTP），以及站点品牌、页脚、备案和自定义页面内容。运行策略默认值来自应用 Settings；站点展示默认值由配置注册表提供；管理员覆盖值统一存入 `global_setting`。

邮箱验证相关设置也存于 `global_setting`：`site_url` 用于生成验证链接，`email_verification_enabled` 控制注册和改邮箱是否必须验证，`email_domain_allowlist` 为逐行维护的可选域名后缀白名单。

邮箱验证链接使用一次性、仅保存哈希的 Token，默认有效期 30 分钟。用户存在 `pending_email` 时，邮件通知投递会被抑制；验证成功后才将其提升为有效 `email`。管理员可在“通知设置 → 邮件设置”中向任意地址发送测试邮件，测试操作只使用已保存的 SMTP 配置。

## 2. 配置分类

| 类别 | 存储位置 | 示例 | 管理方式 |
| --- | --- | --- | --- |
| 部署与连接 | 环境变量/部署清单 | 数据库地址、连接池、监听地址、端口、迁移开关 | 运维变更，通常需重启 |
| Secret | 部署密钥或数据库记录 | JWT Secret、Refresh Pepper、SMTP 密码、TLS 私钥 | SMTP 密码可由管理员写入数据库并由管理员 API 返回明文；其余密钥不经普通 API |
| 全局运行策略 | 数据库 `global_setting` | 检查周期、任务/通知重试、Webhook 代理、Scheduler 批量、注册开关、SMTP 投递参数 | 管理员 API，审计、版本控制，已注册项均运行期生效 |
| 用户偏好 | `AppUser.preferences` 的白名单字段 | 语言、时区、默认监控开关 | 当前用户 API，不影响全局行为 |

数据库或项目初始化无关的环境变量，只有在其同时满足“业务策略、可由管理员承担影响、数据库不可用时不影响安全启动”时，才允许迁入第三类。Secret 原则上仍留在部署层；SMTP 密码以及可能内嵌认证信息的 Webhook 代理 URL 是允许管理员明文持久化和读取的明确例外。Webhook Endpoint URL 本身禁止内嵌凭据。

## 3. 数据模型与契约

`global_setting` 不得直接对外暴露为自由读写的 key-value API。应用层维护键注册表；每个条目至少包含：

- `key`、值类型、序列化规则、默认值和范围；
- 是否可热更新、目标进程以及最大生效延迟；
- 是否允许管理员查看/修改；
- 与其他键的交叉约束；
- 展示名称、说明和安全等级。

持久化记录应扩展为值、版本、更新时间和更新操作者；修改接口使用 `If-Match` 或显式版本防止静默覆盖。
审计事件保存键名、旧/新值的脱敏摘要、操作者、请求 ID 和时间，不保存 Secret 或超出必要范围的明文。

## 4. 运行流程

```mermaid
flowchart LR
  A[管理员提交配置修改] --> B[认证与 require_admin]
  B --> C[键注册表和交叉约束校验]
  C --> D[版本校验]
  D --> E[短事务写入设置和审计]
  E --> F[返回新版本与生效边界]
  F --> G[API / Worker / Scheduler / Notifier]
  G --> H[下一请求或下一工作循环读取有效策略]
```

读取优先级固定为：数据库有效覆盖值 > 应用 Settings 默认值 > 代码默认值。数据库不存在该键时必须正常回退；
数据库读取、反序列化或校验失败时不得采用未知值，应继续使用最近有效值/默认值并记录可观测错误。

## 5. 分批迁移顺序

1. **基础设施（M4 首个配置提交）**：键注册表、版本字段、专用读写服务、审计、契约测试和管理员只读页面。
2. **验证样例**：把现有成功结果新鲜度策略迁移到新服务；保证旧值兼容并补齐审计。
3. **任务与调度策略**：检查周期、任务租约、任务重试、Scheduler 批量和轮询间隔。
4. **通知设置**：投递超时、通知重试、Notifier 轮询间隔、Webhook HTTP/SOCKS5 代理，以及 SMTP 主机/端口/发件人/账号/STARTTLS 均由数据库管理；代理地址和 SMTP 密码明文写入 `global_setting` 并可由管理员 API 返回，但审计元数据只记录设置键。
5. **产品开关**：注册开关等非敏感开关。每个开关必须有默认行为、回滚方式和权限说明。

每一批必须独立迁移、保留环境变量默认值并带回归测试。禁止一次性删除 `.env` 配置项或将所有
`Settings` 字段无差别复制到数据库。

## 6. 验收与运维

- 非管理员不能读取或修改管理员配置；
- 未注册、越界、交叉约束不满足和版本冲突分别返回稳定错误；
- 两个管理员并发修改同一键不会丢失更新；
- 多进程在声明的最大延迟内使用同一有效版本；
- 回滚产生新的版本和审计事件，不覆盖历史；
- PostgreSQL 集成测试覆盖迁移、并发写入和 Worker/Scheduler/Notifier 的生效边界；
- 配置页面显示值来源（默认值或数据库覆盖）、版本、生效说明和最近审计，不显示 Secret。
